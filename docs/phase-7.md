# Phase 7 — 식물 관리 캘린더

## 구현 동작

- 하단 캘린더 탭을 활성화하고 `/calendar`에 월별 화면을 추가했습니다.
- 이전/다음 달, 오늘 이동, 날짜 선택, 전체/특정 식물 필터를 제공합니다.
- 물주기·식물등·분갈이·비료·사진 일기를 유형별 색상 점으로 표시합니다.
  같은 날짜에 같은 유형이 여러 건이면 점은 하나, 접근성 이름과 목록은 실제 건수입니다.
- 선택 날짜의 목록에는 식물, 기록 유형, 제목/메모, 관리 시각과 식물등 사용 시간을 표시합니다.
  일기는 기존 상세 화면으로, 관리 이벤트는 기존 관리 기록 수정 화면으로 이동합니다.
- 선택 날짜와 필터는 URL `date`/`plant` 매개변수로 유지합니다. 기록 화면에서 브라우저
  뒤로 가기를 하면 이전 선택으로 돌아갈 수 있습니다. 하단 캘린더 탭을 새로 누르면
  오늘/전체 식물로 진입합니다. 잘못된 날짜나 삭제된 식물 필터는 안전하게 대체합니다.
- 기록이 없는 날짜, 식물이 없는 경우, 조회 중·실패·재시도 상태를 제공합니다.

## 데이터와 갱신 정책

`loadCalendar()`는 기존 Repository의 `plants.list()`, `diaries.listByPlant()`,
`careEvents.listByPlant()`를 기존 트랜잭션 안에서 읽습니다. React에서 Dexie를 직접
호출하지 않으며 DB 버전/스키마/Repository 계약/사용자 데이터 모델을 변경하지 않았습니다.
사진 Blob은 조회하지 않습니다. 캘린더용 테이블·캐시 영속화·중복 데이터는 없습니다.

관리 이벤트의 `occurredAt`은 기기의 로컬 날짜로 변환하고 일기는 `entryDate`를 그대로
사용합니다. 생성 시각으로 일기 날짜를 추정하지 않습니다. 날짜 계산만 UTC 기반의
날짜 전용 연산을 사용하므로 월 이동과 윤년 계산이 DST에 흔들리지 않습니다.
같은 날짜의 관리 이벤트는 저장 ISO 문자열의 오프셋과 관계없이 실제 시각 역순입니다.
일기에는 시각을 만들어 붙이지 않고 해당 날짜의 관리 이벤트 뒤에 표시합니다.

기존 저장·삭제 흐름의 `invalidate`, 경로 재진입, 포커스/탭 복귀 재조회로 변경을 반영합니다.
오늘 표시는 1분 간격 및 창 포커스 시 갱신합니다. 일정 예약·타이머·알림 기능은 추가하지 않았습니다.

MVP에서는 모든 식물의 일기·관리 메타데이터를 한 번 읽고 화면에서 날짜와 식물을 필터링합니다.
대규모 데이터에서는 월 범위 Repository 조회로 개선할 여지가 있습니다. 이번에는 DB 인덱스나
스키마를 추가하지 않았습니다.

## UI와 접근성

기존 로컬 Pretendard, 크림/세이지, 카드/하단 네비게이션 스타일을 유지합니다.
320px에서 날짜 버튼은 44×56px이며 가로 넘침이 없습니다. 고정 네비게이션 아래에
마지막 기록이 가려지지 않도록 기존 앱 셸 하단 여백을 재사용합니다.

날짜는 table/요일 헤더/버튼으로 구성하며 선택 날짜 하나만 Tab 순서에 포함합니다.
방향키는 ±1/7일, Home/End는 주의 처음/끝, Page Up/Down은 이전/다음 달로 이동합니다.
선택은 `aria-pressed`, 오늘은 `aria-current="date"`, 하단 활성 탭은 `aria-current="page"`로
표시합니다. 유형과 건수를 날짜의 접근성 이름으로 읽어 색상만으로 구분하지 않습니다.

## 검증 결과

- `npm run check`: 타입·린트·포맷·248개 테스트(23개 파일)·빌드 통과.
  기존 222개 테스트에 신규 26개를 추가했습니다.
- 월/연도 경계, 평년/윤년 2월, 6주 달력, 날짜 이동과 잘못된 URL 날짜를 검증했습니다.
- 로컬 날짜/과거 일기/다중 이벤트/시간대 오프셋별 정렬/사진 비조회/오류 전달을 검증했습니다.
- 식물 필터, 같은 유형 중복 점, 날짜별 목록, 월 건수, 키보드 이동, 빈 데이터/재시도를 검증했습니다.
- 기존 관리 폼에서 수정 저장 후 반영, 기존 일기 상세에서 삭제 후 점·목록 갱신과 관리 이벤트
  유지, Repository 변경 후 포커스 재조회로 생성·수정·삭제 반영을 검증했습니다.
- 서울/로스앤젤레스 시간대에서도 날짜·조회 테스트 16개를 별도로 실행했습니다.
- 실제 IAB의 320×740, 390×844 viewport로 확인했습니다. 원래 데이터가 있는 5173 origin은
  건드리지 않고 별도 `http://127.0.0.1:5174`의 기존 검증용 식물만 사용했습니다.
  물주기·식물등·분갈이·비료·일기 총 5개 검증 기록을 UI로 생성했고 분갈이와 비료 날짜를
  각각 10월 21일/23일로 수정했습니다. 이 테스트 기록은 5174 origin에 남아 있습니다.
- 새로고침 후 기록 복원, 일기 상세 이동, 2026년 12월 → 2027년 1월 이동,
  식물 필터의 빈 상태와 가로 스크롤 없음, 기존 Pretendard를 확인했습니다.
  모바일 기기의 실제 가상 키보드/VoiceOver 검증은 포함하지 않습니다.
- 캘린더 JS 약 8.22kB(gzip 3.34kB)는 경로별 지연 로딩입니다.
  기본 JS는 약 502.30kB(gzip 155.51kB)로 기존 500kB 경고는 유지되며 빌드는 성공합니다.
  이번에 기존 번들의 분할/의존성 교체/경고 한도 변경은 하지 않았습니다.
