확인 날짜: 2026-10-26. Phase 6 학명 추천, 추천 UI 간소화, 아데니움 2종 추가를
`feat: add plant scientific name suggestions` 커밋으로 정리하는 작업의 점검 기록입니다.

## 포함 범위와 데이터 보호

- 32종 로컬 카탈로그, 검색 함수·테스트, 후보 선택/펼침 UI, 등록·수정 폼 연결과 테스트.
- 분류 출처·확인 날짜·이용 고지, 구현/점검 문서와 320px·390px 브라우저 검증 캡처.
- 기존 사용자 DB를 열거나 초기화하지 않았습니다. 회귀 테스트는 fake-indexeddb의
  독립 테스트 DB에서 실행합니다.
- 추적 파일과 미추적 후보 184개에 대해 키 패턴 및 민감/임시 파일명을 점검했고
  해당 후보를 발견하지 않았습니다. 생성된 빌드·의존성·로그·로컬 환경 변수·백업 ZIP은
  기존 ignore 규칙으로 제외합니다. 포함 이미지들은 앞선 작업에서 생성한 UI 검증 캡처입니다.
- 기존 식물·대표 사진 CRUD, 관리 기록, 사진 일기, 백업·복원 테스트를 포함해
  222개 테스트(20개 파일)와 타입·린트·포맷·빌드를 검증했습니다.

## 501kB 경고의 원인

현재 프로덕션 기본 JS 청크는 약 501.05kB, gzip 약 154.99kB입니다.
경고 기준은 설치된 Vite 8.3.5의 기본 `chunkSizeWarningLimit: 500`입니다.
압축 전 전송 원본에 해당하는 **minify 후 JS 크기**에 대한 경고로, gzip 크기 기준이나
빌드 실패를 의미하지 않습니다.

Vite 설정과 소스의 import 구조를 읽고, 기존 설정을 그대로 사용한 메모리 내 빌드의
`generateBundle` 메타데이터를 조사했습니다. 분석 결과는 임시 디렉터리에만 저장했습니다.
`write: false`로 분석 빌드 산출물은 쓰지 않았으며 번들 구조나 의존성은 변경하지 않았습니다.

- `src/app/routes.tsx`에서 홈·식물 등록/수정·상세·관리 기록·일기 작성/상세를
  정적으로 import하므로 각 화면 및 관련 서비스가 기본 청크에 모입니다.
- React DOM, React Router, Dexie가 기본 청크의 주요 라이브러리입니다.
  분석용 모듈 `renderedLength` 합은 각각 약 537kB, 210kB, 203kB입니다.
  이 값은 **청크 전체 minify 이전** 지표이므로 501kB와 직접 합산하거나
  minify 후 모듈별 크기로 해석하면 안 됩니다.
- 같은 지표에서 앱 소스는 약 133kB, 그중 카탈로그 JSON은 약 10.3kB입니다.
  신규 아데니움 전 빌드는 약 499.92kB였고 추가 후 약 501.05kB로 경고선을 넘었습니다.
  따라서 카탈로그 추가는 임계점을 넘긴 계기이며 공통 런타임·여러 화면의 정적 로딩이
  기본 청크 크기의 주된 배경입니다.
- 백업 경로는 이미 lazy import입니다. 약 28.72kB의 별도 BackupPage 청크에
  백업 화면·서비스 및 fflate가 포함돼 기본 청크 경고의 직접 원인이 아닙니다.
- 로컬 Pretendard woff2 약 2.06MB는 별도 폰트 파일이며 JS 501kB 경고와 별개입니다.
  Lucide는 사용 아이콘 위주로 포함되고 사용하지 않는 전체 아이콘 소스가 모두 들어간 것은 아닙니다.

## 다음 개선 방향 — 이번에는 미적용

1. 처음부터 필요하지 않은 식물/관리 기록/사진 일기 편집 화면을 경로 단위 lazy import로
   나누고, 로딩 피드백·직접 URL 진입·실패 복구를 함께 검증합니다.
2. 카탈로그와 추천 UI를 식물 편집 경로에서 로드하도록 범위를 줄입니다.
3. 필요하면 공통 라이브러리의 캐시 분리 전략을 검토하되, vendor 청크 분리만으로 전체
   다운로드나 파싱 비용이 줄지는 않으므로 실제 초기 로딩·재방문 캐시 지표로 판단합니다.
4. 라이브러리 제거·교체나 경고 한도 상향보다 먼저 경로 분할 효과를 측정합니다.
   경고 한도만 높이면 실제 로딩 비용은 개선되지 않습니다.

이번 Git 정리에서는 Vite 설정, import 구조, 런타임 동작, DB 스키마를 변경하지 않았습니다.
