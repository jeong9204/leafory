# Phase 4B-1 — 빠른 관리 기록

2026-10-25 검증. 기존 크림·세이지 스타일, 식물 CRUD와 대표 사진 정책을 유지했다. DB v1과 Repository 계약은 변경하지 않았고 신규 의존성은 없다.

## 동작

- 홈 물주기는 현재 기기의 시각을 `new Date().toISOString()`으로 기록한다. 처리 중 버튼 비활성화와 동기 ref 잠금으로 빠른 반복 클릭을 막는다. 성공·실패 안내를 표시한다. 저장 완료 뒤의 의도적인 재기록은 허용한다.
- `/plants/:id/care/new`: 물주기·식물등·분갈이·비료를 선택한다. 로컬 날짜·시각과 선택 메모를 입력하며 식물등은 시간·분을 입력한다. 저장은 양의 정수 분 단위다. 분 입력은 0~59, 메모는 3,000자까지다. 실재하지 않는 날짜와 DST로 건너뛴 로컬 시각을 거부한다.
- `/plants/:id/care/:eventId/edit`: 같은 폼으로 수정한다. 메모나 종류만 수정하면 원래 저장된 초·밀리초를 유지한다. 다른 식물에 속한 기록 주소는 거부한다.
- 상세 타임라인에는 로컬 날짜와 시각, 종류, 사용 시간, 메모와 수정·삭제 동작을 표시한다. 삭제는 확인창을 거치며 실패하면 기록을 유지하고 재시도할 수 있다.
- 성공한 변경은 Provider revision을 갱신해 홈/상세/최근 기록을 다시 조회한다. 마지막 물주기는 가장 최근 `occurredAt`, 오늘 식물등은 기기 로컬 날짜가 오늘인 기록만 합산한다. 삭제/수정도 같은 경로로 재계산하며 상태를 자동 판단하지 않는다.
- React 컴포넌트는 Repository만 호출한다. 수정·삭제 시 소속 확인과 변경은 하나의 Repository 트랜잭션에서 처리한다.

## 식물 폼 UX

사진 미리보기는 154px에서 136px로 축소했다. 식물 등록·수정 및 빠른 기록 폼에서는 하단 네비게이션과 그 예약 여백을 제거했다. 입력 폰트는 16px를 유지했다.

라우터를 `createBrowserRouter`/`RouterProvider`로 구성해 `useBlocker`가 링크·취소·브라우저 뒤로 가기를 처리한다. 변경 전 값으로 돌아오면 확인하지 않는다. 사진 변경·처리 중도 이탈 보호 대상이며, 저장 성공 시만 보호를 우회한다. 저장 중에는 이탈 확인창에서 나가기를 막고, 실패 시 값과 사진을 유지한다. 새로고침/탭 닫기는 `beforeunload` 기본 확인을 사용한다. 브라우저 정책에 따라 강제 종료·모바일 앱 종료 때는 이 확인이 표시되지 않을 수 있고 초안 자동 저장은 하지 않는다.

## 자동 검증

`npm run check` 통과: 타입 검사, 경고 없는 ESLint, Prettier, **12개 파일 / 140개 테스트**, 프로덕션 빌드.

기존 118개 테스트를 유지하고 기능 활성화에 맞는 기대값만 변경했다. 신규 22개 테스트는 과거 물주기 생성·수정·삭제와 마지막 날짜 재계산, 오늘 식물등만 합산, 삭제 후 재계산, DB 재연결, 로컬 날짜 변환, 잘못된 시간·분, 기록 소속 검증, 타임스탬프 정밀도 유지, 중복 물주기/제출, 저장·삭제 실패 및 재시도, 입력 유지, 빈 상태, 이탈 취소/확인, 새로고침 방지를 검증한다.

처음 전체 병렬 실행에서 기존 테스트를 포함한 시간 초과가 발생했다. 워커 2개로 제한한 재검사에서 통과해 기본 테스트 설정도 `maxWorkers: 2`로 제한했다. 타임아웃을 늘리거나 검증을 제거하지 않았다.

## 실제 브라우저 검증

로컬 Vite 앱과 실제 IndexedDB에서 직접 만든 `검증용 초록이`로 검증했다. DB 직접 주입과 목업 자동 등록은 사용하지 않았다.

1. 식물 등록, 수정되지 않은 폼 취소, 변경 후 링크 이탈 확인/계속 작성, 브라우저 뒤로 가기 확인/나가기.
2. 홈 물주기 → 당일 날짜·오늘·주간 기록 수 반영.
3. 빠른 기록으로 식물등 1시간 30분 저장 → 오늘 90분.
4. 물주기 일시를 10월 20일 09:15로 수정 → 마지막 날짜와 타임라인 순서 반영.
5. 물주기 삭제 → 마지막 물주기 `기록 없음`.
6. 식물등 30분 추가 → 120분; 해당 기록 삭제 → 90분.
7. 새로고침 후 이벤트·메모·90분 합계 복원 확인.
8. 320×760, 390×844 화면 육안 확인. 홈·상세·빠른 기록·식물 폼에서 가로 넘침 없음. 320px DOM의 실제 scrollWidth도 320px 확인. 390px 폼과 상세 캡처에서도 겹침 없음.
9. 검증 후 직접 만든 식물과 연결 기록을 삭제해 초기 빈 DB로 복원했다. 캡처는 정리 전 기록이다.

실제 iOS/Android 소프트웨어 키보드 동작은 데스크톱 브라우저 뷰포트 검사로 대체할 수 없으므로 기기 실사용 확인이 남는다. 빠른 중복 클릭·저장 실패는 자동 테스트에서 지연/오류를 주입해 확인했다.
