## 브라우저 검증과 변경 전후 자료

- 로컬 Chromium 계열 QA 브라우저, 실제 CSS viewport 320×844 / 390×844.

- 양쪽 모두 로딩 완료 후 촬영했다. 샘플 이벤트의 ID 및 타이머 상태는 격리 환경마다 다르므로, 일부 기록 순서·타이머 숫자는 디자인 차이가 아니다.
- 12개 화면 × 2개 너비에서 `scrollWidth === innerWidth`, 깨진 이미지 0개. 측정값은 로컬 검토 자료 `docs/screenshots/phase-12b/layout-checks.json`에 보존한다.
- 식물 관리 메뉴 → 삭제 확인 → 취소, 타이머 시작 → 일시정지 → 종료 확인 → 돌아가기, 학명 추천 선택·펼침, 작성 중 이탈 확인, 성장 사진 두 장 선택·비교, 사진 탭을 브라우저에서 확인했다. 실제 사용자 데이터에는 접근하지 않았다.

- 상세 화면 끝에서 메모 하단은 약 y=744, 고정 메뉴 상단은 y=768로 두 너비 모두 약 24px 여유가 있었다. 스크롤 중 메뉴는 viewport 하단에 고정된다.

390px 변경 전후 비교는 왼쪽 변경 전 / 오른쪽 변경 후로 촬영했다. 캡처와 측정 JSON은 `docs/screenshots/phase-12b/`에 로컬 검토 자료로 보존하며, 배포에 필요하지 않으므로 Git 커밋에서 제외한다. 원격 저장소에는 이 문서의 측정 결과만 포함한다.

## iPhone 직접 확인 항목

로컬 Chromium 검증은 iPhone 실기기 검증을 대체하지 않는다. 아래 항목은 승인된 Preview 배포 후 실제 iPhone에서 확인해야 한다. 테스트 전 ZIP 백업을 권장하며 앱 삭제·Safari 사이트 데이터 삭제·IndexedDB 초기화는 하지 않는다.

1. 기존 식물·일기·사진과 실행 중인 타이머가 유지되는지 먼저 확인한다.
2. 식물 상세, 등록·수정, 사진 일기 작성·상세, 성장 비교, 캘린더의 색상·텍스트·버튼을 확인한다.
3. 타이머 시작·일시정지·재개·종료 확인 UI를 확인한다.
4. 설치된 PWA와 Safari에서 노치·상태바·홈 인디케이터의 실제 safe-area.
5. 네이티브 날짜·시각 선택기, select, 키보드 노출 시 입력칸·저장 버튼 가림 여부.
6. 상세 화면 끝까지 스크롤 후 메모·마지막 기록·고정 메뉴의 간격.
7. 사진 원본 로딩·성장 비교, 타이머 상태별 버튼·확인 모달의 읽기 편의성.
8. 업데이트 알림이 있을 때 크림 배경과 상태 안내의 대비, 작성 중 업데이트 차단 유지.
9. 온라인에서 업데이트·필요 파일 로드를 마친 뒤 비행기 모드에서 기존 설치 앱의 재실행과 사용자 기록 보존. 이번 작업에서는 실제 설치 환경의 캐시를 조작하지 않았다.
